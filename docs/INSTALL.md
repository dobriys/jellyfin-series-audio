# Установка Series Audio 0.4.0

Сборка для **Jellyfin Server 12.4.0**, образа `lscr.io/linuxserver/jellyfin` и Docker / Portainer. Не устанавливайте её на другую версию без проверки совместимости. Обновление контейнера с тегом `latest` может изменить версию сервера.

## Обновление с предыдущей версии

1. Перенесите и распакуйте новый архив, как указано ниже.
2. Остановите контейнер Jellyfin в Portainer и выполните команду установщика из раздела 2.
3. Запустите тот же контейнер. При обновлении существующее подключение скрипта подходит. Обновите Jellyfin в браузере без кеша.
4. Откройте сезон с несколькими озвучками. При обновлении с 0.2.0, 0.2.1 или 0.3.0 сохранённые настройки сезонов доступны сразу. При обновлении с 0.1.0 выберите озвучку для каждого нужного сезона. Прежний выбор для сериала пригодится при откате.

## 1. Перенести архив на сервер

Распакуйте `SeriesAudio-0.4.0-jellyfin-12.4.zip` на машине, где работает Docker. Внутри находятся DLL, установщик, скрипт подключения веб-панели и контрольные суммы. Установщик проверяет суммы перед копированием.

## 2. Установить файлы

В терминале сервера, из распакованной папки:

```sh
sudo python3 install.py \
  --config /home/stanislav/docker/jellyfin/config \
  --init-script /home/stanislav/docker/jellyfin/series-audio-init.sh
```

Установщик:

- проверяет, что указана существующая папка конфигурации LinuxServer;
- переносит предыдущую сборку и копирует настройки плагина в `config/series-audio-backups/`, если они уже есть;
- копирует DLL в `config/data/plugins/SeriesAudio_0.4.0.0/`;
- создаёт отдельный скрипт подключения панели, не меняя `custom.js`;
- **не перезапускает контейнер** и не изменяет настройки озвучки пользователей.

Если контейнер использует другой путь `/config`, укажите его host-путь. Для официального образа `jellyfin/jellyfin` этот установщик не подходит без адаптации путей.

## 3. Подключить панель в Portainer при первой установке

В существующий список `volumes` сервиса `jellyfin` добавьте одну строку:

```yaml
- /home/stanislav/docker/jellyfin/series-audio-init.sh:/custom-cont-init.d/99-series-audio:ro
```

Остальные тома сохраните. Примените изменение стека с пересозданием контейнера. Это прервёт активное воспроизведение. Не выбирайте обновление/pull образа: сборка подготовлена под установленную 12.4.0.

При каждом старте скрипт добавляет загрузку панели в `index.html` внутри контейнера, если её ещё нет. Относительный адрес работает и с настроенным Base URL. Только размещения `custom.js` в папке Web недостаточно: страница должна подключать его явно. Для этой установки `custom.js` не требуется.

## 4. Проверить

1. В панели управления Jellyfin → Плагины найдите **Series Audio 0.4.0.0**, статус Active.
2. Обновите Jellyfin в браузере без кеша. Откройте общую страницу сериала или отдельный сезон с несколькими озвучками.
3. На странице сериала в блоке «Озвучки по сезонам» выберите нужный сезон и сохраните озвучку в его строке. На странице сезона используйте блок «Озвучка сезона» над списком серий.
4. Проверьте подпись «По умолчанию» на страницах сериала, сезона и серии. Если в сезоне одна дорожка, отображается только подпись.
5. Запустите серию на Android TV и проверьте фактическое название дорожки в плеере. Повторите на следующей серии.
6. Выполните [проверку на телевизоре](TV-CHECKLIST.md): старт серии, следующая серия, ручное переключение, второй профиль, сброс.

Данные предпочтений в этой конфигурации хранятся в `config/data/data/series-audio/preferences.json`. Не меняйте файл при работающем сервере. Настройки библиотек и существующие пользовательские настройки Jellyfin плагин не переписывает.

## Откат

1. Остановите контейнер.
2. Переместите `config/data/plugins/SeriesAudio_0.4.0.0` в папку вне `plugins` — например, в `config/series-audio-backups/disabled-0.4.0`.
3. Удалите добавленную строку bind mount из стека и пересоздайте контейнер: оригинальный `index.html` будет восстановлен из образа.
4. Обновите страницу без кеша. Сохранённые предпочтения можно оставить для повторной установки.

Для возврата к предыдущей версии выполните первые два шага отката, верните её папку из резервной копии в `config/data/plugins/` и запустите контейнер с прежним подключением скрипта.
